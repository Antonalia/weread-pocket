# 开发说明

## 工具

- Node.js 20 或更新版本；使用内置标准库，不需要额外打包器。
- Windows PowerShell：仅 ZIP 打包脚本需要。
- Obsidian 桌面版及一个专用测试仓库：用于验证真实网页、登录、画布与交互。

项目没有自动部署、自动安装到仓库或自更新步骤。构建和打包输出限定在本项目文件夹。

## 构建

```bash
npm ci
npm run build
npm test
```

构建按顺序完成：

1. 将 `src/create-literature-cards.js` 同步到原生阅读桥接的 `WRP_LITERATURE_LAYOUT_START / END` 标记内。
2. 将 `src/native-underline-interaction.js` 同步到桥接的 `WRP_UNDERLINE_INTERACTION_START / END` 标记内。
3. 将 `src/native-reader-bridge.js` 同步到 `src/main.js` 的原生绑定函数。
4. 将 `src/local-book-store.js`、`src/local-reader-surface.js` 与 `src/local-books-integration.js` 嵌入 `src/main.js` 的 `WRP_LOCAL_BOOKS_START / END` 区块，并连接本地来源。
5. 生成根目录 `main.js`，随后进行语法检查。

独立 helper 是编辑源；`src/main.js` 和桥接中的相应嵌入区块由构建同步。请避免同时手工编辑同一段 helper 的两份副本。缺失或重复的嵌入标记会使构建失败。

构建不含时间戳，同样源码应生成相同的 `main.js`。不做代码混淆，便于人工审查。

## 检查

`scripts/check.cjs` 检查插件元数据、源码语法、构建一致性，以及 `tests/validate-*.cjs` 中的回归测试。检查不访问真实账号、官方网络接口或个人仓库。

本地测试只能验证被模拟的行为。提交发布候选前，还需在专用仓库检查：

- 四种阅读位置切换后是否复用同一会话。
- 本地书架添加、查找、打开和移除是否正确；导入是否复制到 `WeRead Pocket/`、保留原文件；重复导入、同名文件、缺失路径、不可读文件和错误格式是否正确处理。
- 旧版外部书架引用是否迁入受管理的图书文件夹并保留逐书进度；点击其中的 EPUB、TXT 是否使用本插件，其他位置是否保持原有文件打开方式。
- EPUB 阅读顺序与目录、TXT 编码与章节切分是否正确；当前章节导航与每本书的阅读位置是否恢复。
- 跨章节连续阅读是否自动衔接相邻章节、保持滚动锚点并隐藏章节按钮；向前与向后滚动时是否释放远离章节、常驻章数是否最多三个；关闭开关与分页模式是否保持各自行为。
- 本地书与微信读书往返切换是否保存最近阅读地址与逐书进度、释放上一来源的 DOM、图片 URL、文件句柄和网页调试连接；以本地来源启动时是否不创建官方网页，返回微信读书是否重新加载且保留登录。同一来源的四种窗口位置切换仍须复用原阅读表面；迟到的章节读取结果不得覆盖新书或新来源。
- 本地 EPUB 是否拒绝脚本、外部资源及路径越界；导入失败后是否释放文件句柄与临时数据。
- 「本地正文排版」默认原书 / 原文排版：EPUB 的安全本地文本样式是否严格限定在阅读器内，字号、缩进、行距、段距与文字对齐是否保留；TXT 的原文行首空格与换行是否保留，背景和文字颜色是否仍跟随主题。外部 CSS、字体、脚本、定位样式、URL 与 @import 不得进入活动阅读界面。
- 自定义排版的 EPUB、TXT 是否应用现有窗口字体与间距，普通正文是否统一首行缩进两个字，已有段首缩进是否归一化且不叠加；标题、列表、表格、代码与文献卡片是否保持各自布局。
- 卡片边框在滚动、缩放和窄窗时是否连续；标题、摘录、正文是否同宽。
- 字号、行距、段距与留白是否按位置和显示模式分别记忆，并能恢复默认。
- 四个位置的卡片开关是否独立、旧版全局偏好是否迁移、当前菜单是否只影响当前位置；为其他位置开启卡片时是否保留当前分页模式。
- 热门划线的八项偏好是否独立记忆，旧版全局值是否迁移，当前菜单是否仅修改当前外观与位置，修改其他项是否保持当前页面；点击是否打开正确位置的公开想法，拖选文字是否正常。
- 快速收起 / 恢复在正文获得焦点时是否有效。
- 四个阅读控制快捷键是否在 Obsidian 主界面与阅读正文获得焦点时均生效，且不移动当前焦点；滚动是否连续每次约三行、按住可重复，分页是否前后翻页，章节是否按一下切换一章、遵守书籍边界，执行中的重复请求是否忽略且不积攒队列。两种来源、四种位置、普通与卡片外观均需覆盖。
- 快捷键更改、清除和恢复默认是否即时应用于宿主与官方网页；空自定义绑定是否保持禁用，自定义绑定是否避免重复执行。未加载图书时不得创建额外网页，插件卸载后不得保留监听。
- 官方网页未获得焦点时，Electron 原生键盘通道是否产生真实 `isTrusted` 键盘事件，桥接是否将原始事件传入 `handlePrevChapter` / `handleNextChapter`，并保持主界面焦点。验证章节 UID、边界与处理结果是否通过只读状态确认，导航是否等待官方异步结果或失败；函数缺失、未就绪或章节不可用时应停止，不更改官方权限状态。动态桥接脚本须保留 sourceURL 标注，避免官方堆栈处理遇到缺失脚本名。来源切换或桥接销毁后须移除对应 document 监听。
- 关闭笔记面板与阅读器、卸载插件后是否清理资源。
- 主题跟随、登录、目录滚动和失败提示是否正常。

不要在测试夹具、报错日志或截图中保留 Cookie、登录资料、真实书籍进度、公开想法内容或受版权保护的正文。

## 架构

`src/main.js` 负责 Obsidian 视图、工具栏、设置、持久会话和网页外观。

阅读控制注册为 Obsidian 命令，宿主使用标准快捷键路由，焦点在笔记编辑器时也能控制当前阅读器；不注册操作系统全局快捷键。绑定从 Obsidian 快捷键管理器即时读取，空自定义数组代表禁用，设置页只提供跳转与恢复默认。官方网页通过现有 guest 键盘监听使用同一绑定，本地正文通过现有键盘路由执行。滚动与章节操作直接作用于当前来源，不调用聚焦阅读器的翻页入口、不创建额外实例；按住滚动键可重复；官方网页的章节与收起命令忽略自动重复，宿主沿用标准命令路由，章节执行中的重复请求忽略且不积攒队列。

官方章节控制使用 Electron 的原生可信键盘通道：宿主向现有网页发送 `Ctrl+Alt+Shift+F13` / `F14` 的 `webview.sendInputEvent`，无需先聚焦网页。原生桥接在 document 的 keydown 监听中接收并检查浏览器产生的原始 `isTrusted` KeyboardEvent，再将该事件传给官方 `handlePrevChapter` / `handleNextChapter`；内部键位不作为用户默认快捷键。桥接只读查询当前章节 UID、相邻章节与就绪状态，以确认边界及执行结果；不伪造 `isTrusted`，不合成 MouseEvent，也不改写官方购买、会员或其他权限状态。桥接销毁时清理 document 监听。

通过 CDP 注入的原生桥接函数标注 `//# sourceURL=weread-pocket-native-reader.js`，为动态脚本提供稳定文件名，兼容官方导航中的堆栈处理。章节导航等待官方处理器的异步结果，并结合章节状态确认完成；官方返回失败或异常时停止，不将“已收到按键”视为成功，也不排队积攒重复请求。公开报告只保留结构和成功状态，不记录用户的章节标识或正文。

本地图书来源分为三个模块：`src/local-book-store.js` 处理只读文件访问与 EPUB/TXT 解析；`src/local-reader-surface.js` 使用宿主 DOM 显示章节、目录和现有卡片外观，并管理按需加载的相邻章节窗口；`src/local-books-integration.js` 管理受控文件夹中的图书、书架索引与逐书进度，将来源切换与原有窗口、工具栏和生命周期连接。跨章节连续阅读最多保留三个相邻章节 DOM；关闭时只保留当前章。本地来源不创建或保留官方网页。切换来源前保存逐书进度或最近网页地址，随后释放上一来源的显示资源；官方 Cookie 仍在持久分区中，返回微信读书重新创建一个网页实例并加载保存的地址。同一来源的窗口位置切换只移动当前阅读表面，不重新创建实例。

本地功能的设计参考了 [UNreader 的公开 README](https://github.com/UNcore-gh/UNreader#readme) 中的 EPUB 目录、TXT 章节识别与逐书进度工作流；未引入其私有开发源码或编译包。本地解析与界面代码由本项目独立实现。

`src/native-reader-bridge.js` 连接原生阅读器，保留原生正文画布、文字偏移与阅读进度。卡片 helper 负责装饰布局；划线 helper 负责点击命中、请求去重、失效检查及笔记面板。

本地导入通过文件复制将 EPUB、TXT 保存到 `WeRead Pocket/`，外部原书不被修改；书架索引、元数据和进度仍保存在插件数据中，不把正文嵌入设置。旧版外部引用迁移时保留逐书进度。移出书架仅删除记录，不删除图书文件。解析器使用 Node.js 标准库按需只读读取受管理的图书。个人文件名和路径不能加入公开测试报告。

微信读书概要笔记同步的命令、设置和请求逻辑已移除。升级不会自动删除用户已有笔记。

运行时 `obsidian` 模块由宿主提供；Electron 的 `@electron/remote` 来自桌面宿主。项目不会从 npm 下载或捆绑微信读书的官方前端代码。

更多实现依赖与限制见 [compatibility.md](./compatibility.md)。
